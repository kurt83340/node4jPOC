# Le POC : un banc d'essai de techniques

Un seul jeu de données, 10 questions de référence, et plusieurs techniques comparées sur ces mêmes questions :

1. Cypher à la main : modélisation du graphe et requêtes écrites à la main. Ces requêtes servent aussi de vérité de référence pour les autres techniques.
2. Agent text-to-Cypher via MCP : serveur officiel `neo4j/mcp` (v1.6.0 du 2026-09-10 ; outils `get-schema`, `read-cypher`, `write-cypher`, `list-gds-procedures` ; mode lecture seule possible ; nécessite APOC). La v1.6.0 déprécie les variables `NEO4J_*` au profit de `NEO4J_MCP_*`, mais la doc n'est pas encore à jour. Autre option : le serveur hébergé « MCP for Aura », inclus dans l'offre Free, avec connexion OAuth. N'importe quel client MCP s'y branche : Claude Code, n8n (en HTTP streamable), ADK…
3. GraphRAG : recherche vectorielle dans les descriptions en français, puis parcours du graphe pour le contexte. Piste : `neo4j-graphrag` (Python, v1.21.0 ; Claude via `AnthropicLLM` ; pas d'embedder Anthropic). Il faut un embedder multilingue, car celui par défaut (all-MiniLM-L6-v2) ne gère que l'anglais. La recherche vectorielle passe par la clause Cypher `SEARCH` ; `db.index.vector.queryNodes` est déprécié depuis 2026.04.
4. Aura Agent, la solution gérée de Neo4j (disponible depuis le 2026-02-03) : agent généré à partir du schéma, déployé en MCP ou en REST. Sur AuraDB Free, il est en lecture seule et ne garde pas l'historique des conversations.
5. En option, la mémoire d'agent avec `neo4j-agent-memory` (Python 0.6.0, TypeScript 0.5.0, expérimental).

Livrable final : un tableau comparatif qui croise chaque technique et chaque question, avec ces critères : réponse juste, sources citées, temps de réponse, coût, effort de mise en place.

Hors périmètre pour l'instant : les briques Google Cloud (agent Neo4j dans Gemini Enterprise ; Pub/Sub, qui passe par du CDC réservé aux offres Enterprise ; Aura Graph Analytics avec BigQuery).

# Le jeu de données : Pokémon (PokéAPI)

Fichiers CSV publics : https://github.com/PokeAPI/pokeapi/tree/master/data/v2/csv
Licence BSD-3 pour PokéAPI ; l'univers Pokémon appartient à Nintendo, donc usage d'apprentissage perso uniquement.

Faits vérifiés le 2026-09-26 :

- Le français correspond à `language_id = 5` (languages.csv).
- 1 025 espèces, toutes avec leur nom français (`pokemon_species_names.csv`). `pokemon.csv` compte 1 351 lignes, formes alternatives comprises.
- Les types sont traduits en français (`type_names.csv`). Garder les 18 types classiques et ignorer Stellaire, ??? et Obscur. La table des faiblesses `type_efficacy.csv` fait 324 lignes (18 × 18).
- 7 116 descriptions en français couvrent 898 espèces (`pokemon_species_flavor_text.csv`), souvent répétées d'un jeu à l'autre. Exemple : « On raconte que la flamme du Dracaufeu s'intensifie après un combat difficile. »
- `pokemon_moves.csv` fait 638 321 lignes (une par jeu et par méthode d'apprentissage), mais ne contient que 99 509 couples Pokémon–attaque distincts. Créer une relation par couple, avec le détail (méthodes, niveau) en propriétés.
- Autres tables : `moves` 937 lignes, `abilities` 374, `pokemon_types` 2 116, `pokemon_abilities` 2 943, `pokemon_evolution` 676.
- Taille estimée du graphe complet : environ 10 000 nœuds et 113 000 relations.

Modèle proposé, à challenger (c'est un exercice de modélisation) :

- Nœuds : `Pokemon`, `Type`, `Attaque`, `Talent`, `Description`.
- Relations aux noms explicites en français, ce qui aide aussi le text-to-Cypher : `A_LE_TYPE` ; entre types, `SUPER_EFFICACE_CONTRE`, `PEU_EFFICACE_CONTRE` et `SANS_EFFET_CONTRE` ; `EVOLUE_EN` ; `APPREND` ; `A_LE_TALENT` ; `A_POUR_DESCRIPTION`.
- Statistiques (PV, attaque, défense, vitesse…) en propriétés du nœud `Pokemon`.
- Question ouverte : espèces ou formes (Méga, Alola…) ? Commencer par les formes par défaut ?

Exemples de questions, à compléter jusqu'à 10 :

- « Quelles attaques font le plus mal à Dracaufeu ? » Réponse attendue : Roche ×4, car il est Feu et Vol. Technique visée : Cypher.
- « Propose une équipe de 6 qui couvre les faiblesses de la mienne. » Technique visée : agent en plusieurs étapes.
- « Quel Pokémon vit près des volcans ? » Technique visée : GraphRAG sur les descriptions.

# Infrastructure

- AuraDB Free pour commencer, car Aura Agent en a besoin. Neo4j annonce deux limites contradictoires : 200 000 nœuds et 400 000 relations dans sa FAQ, 50 000 et 175 000 sur la page produit. Vérifier la vraie limite à la création. L'instance se met en pause après 72 h sans activité, puis elle est supprimée après 30 jours de pause.
- Solution de repli : Neo4j en local avec Docker (`neo4j:2026.09.0`), sans limite.
- Identifiants : le fichier téléchargé à la création de l'instance (`Neo4j-….txt`) est déjà au format `CLE=valeur`. Il va dans `.env`, qui est gitignoré. Ne jamais afficher le mot de passe, ni le committer.

# Jalons

1. Instance créée ; données chargées par un script réexécutable sans créer de doublons ; modèle documenté ; 10 questions de référence avec leurs réponses attendues, calculées en Cypher.
2. Agent text-to-Cypher via MCP.
3. GraphRAG sur les descriptions.
4. Aura Agent testé et tableau comparatif final.
